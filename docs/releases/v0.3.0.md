# v0.3.0

Blob columns and local-only tables make this the media-storage release. It also includes the multi-tab, sync, and server hardening completed after v0.2.6. All packages move in lockstep.

## Upgrading

- Created records still start as `_status: 'created', _changed: ''`, but later edits now accumulate column names in `_changed` while the status remains `created`. This lets an accepted push whose local mark was interrupted reconcile newer server values without losing edits made after the push snapshot. Code that reads internal bookkeeping fields may observe the new column list.
- Integer-valued numbers outside JavaScript's safe range are rejected during record sanitization. SQLite can store them but JavaScript cannot read them back exactly; use a string column for larger integers.
- Hand-written HTTP bindings that use blob columns validate decoded engine rows with `wire.localRows`, not `wire.rows`, and encode `wire.pullResult` or `wire.pushResult` before serializing JSON. `@remelondb/nestjs` performs both steps automatically.

## Added

- `c.blob()` stores `Uint8Array` values in Node, web, React Native, and Drizzle/Postgres. Blob values use padded canonical base64 on the JSON sync wire, including nullable blobs and Zod refinements over decoded bytes.
- `table(..., { localOnly: true })` creates an ordinary queryable and migratable table that the sync layer never pushes, pulls, or clears during replacement sync. Local-only deletes are permanent rather than tombstoned. This is intended for device caches such as downloaded media.
- `Database.open({ randomSource })` allows a database to supply its own cryptographic random source without mutating globals.

## Fixed

- Replacement sync now applies only tables present in the response. Omitted tables retain their rows, matching the wire rule that an absent table means no changes. A response that names a local-only table is rejected in normal and replacement modes.
- Pull normalization deduplicates repeated deletion ids, so one remote deletion produces one operation and one observer notification.
- Cross-tab updates from an older schema no longer replace newer cached columns with defaults. Blob-bearing queries compare bytes rather than `Uint8Array` identity, avoiding duplicate emissions for bookkeeping-only broadcasts.
- A pushed creation left dirty by an interrupted mark accepts later server updates while preserving columns edited locally after creation.
- SharedWorker storage-kind mismatches reject `open()` instead of resolving with an error-shaped success. Closing after another tab destroys the database now completes normally.
- The NestJS runtime awaits scopes passed directly to `pull()` and `push()`, preventing a Promise object from becoming a tenant key in custom controllers.
- Live observation failures without `onError` remain unhandled promise rejections rather than timer exceptions; discarded observations remain quiet.
- Memory and reference stores reject invalid garbage-collection floors before `NaN` or `Infinity` can poison issued cursors.
- Invalid ids returned by a server cross-validation hook surface as server errors. Client-originated malformed protocol requests remain `SyncProtocolError` failures.

## Verification

- Blob storage and sync have focused coverage across core, Node, web, React Native, NestJS, Drizzle, and the server conformance suite.
- Local-only tables are covered for querying, migration, sync exclusion, replacement sync, and local deletion.
- Multi-tab behavior is exercised in the browser suite and its Quint model; sync behavior remains covered by the server conformance suite and `docs/sync_model.qnt`.
