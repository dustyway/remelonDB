# v0.1.0

The multi-tab release, and the first minor. On the web, every tab can
now be live on one database: one shared connection behind a
SharedWorker broker, commits broadcast into every tab's record cache,
write blocks serialized across tabs, and sync running in exactly one
tab via a self-healing lease. Opt-in with one driver flag. Around it: a
lifecycle manager that makes the recommended bootstrap three lines on
every platform, React bindings as a core subpath, and a dependency
restructure that turns version-mismatch bugs into loud install-time
warnings — the one change that may need action when upgrading.

## Breaking: core and server are peer dependencies now

`@remelondb/core` moved from a hard dependency of every driver (and
`@remelondb/server` of its consumers) to a peer dependency. Apps must
declare `@remelondb/core` themselves next to their driver — most
already do; those relying on the driver pulling core in implicitly get
an unmet-peer warning until they add it. The point: previously, a
version mismatch between a driver and core silently installed BOTH core
versions, and schema objects built by one copy flowed through code from
the other — a real bug class observed in the wild. With peers, the
package manager reports the mismatch at install time instead.

## New: multi-tab shared mode (web, opt-in)

```ts
new WebSqliteDriver({ shared: true })
```

All tabs route through one SharedWorker to a single SQLite connection —
same-name opens share it instead of contending, so the "open in another
tab" error and the takeover dance disappear where the mode is on.
Three coordination layers ship with it:

- **Change broadcast**: a commit in any tab lands in every other tab's
  record cache and observers, through a new core doorway
  (`database.applyExternalChanges`). Screens mirror without a sync
  round-trip.
- **Write arbitration**: `db.write` blocks (and `db.read` consistency
  windows) are serialized across tabs by a FIFO token queue in the
  broker, so racing read-modify-write converges. The ordering invariant
  that makes arbitration and broadcast compose — a block always reads
  what was serialized before it — is model-checked: `docs/multi-tab.qnt`
  is a CI-typechecked Quint model whose bug-flag variant reproduces the
  lost-update the invariant prevents.
- **Sync lease**: `synchronize` runs only in the tab holding a broker
  lease, renewed by each tick and inherited when the holder closes. A
  naive per-tab sync interval is now correct as written; no more N tabs
  syncing N times or racing each other into push conflicts.

Where `SharedWorker` does not exist (Chrome for Android), the option
falls back to the shipped single-owner behavior — same API, same
errors, takeover UI reachable again — and the fallback is itself part
of the browser test suite. Design, implementation learnings, and the
open questions that keep the mode opt-in for now: `docs/multi-tab.md`.

## New: createDatabaseManager and @remelondb/core/react

The recommended app bootstrap on every platform:

```ts
const manager = createDatabaseManager({
  open: (onTakenOver) =>
    Database.open({ driver: new WebSqliteDriver({ shared: true, takeover: true, onTakenOver }), ... }),
})
const { status, error } = useDatabaseState(manager) // @remelondb/core/react
```

The manager owns the lifecycle so apps cannot get it wrong: concurrent
`init()` calls share one open, a failed open stays retryable instead of
cached, and a superseded attempt's takeover callback can never clobber
a newer database (attempts are epoch-tagged). The React hook is a
`useSyncExternalStore` binding in a new `/react` subpath — react is an
optional peer, nothing loads unless imported, and it works in React
Native unchanged. The tutorial and both todo-sync clients (web and
native) now boot this way.

## Fixed: related() on a dangling belongs_to

`model.related(table)` threw when the foreign key pointed at a record
that no longer exists — a normal state under sync, where a parent can
be deleted while children still reference it. It now resolves `null`,
matching the documented contract, and reads through the same visibility
rules as queries.

## Tests and tooling

Browser test files now run serially: the OPFS SAH pool is one
exclusive, origin-wide resource, and parallel files fighting over it
was the root cause of a long-standing WebKit flake previously absorbed
by retries — the retry crutch is gone. Request handling in the worker
server is serialized across endpoints and covered by property-based
tests. The Android driver CI harness consumes the packed tarballs the
way a real app does, with no dependency rewriting.

## Example

todo-sync now demonstrates the full story: open it in two tabs and they
mirror one live database through the broker; a private window is a
second device syncing through the server; the same manager bootstrap
runs on web and React Native. The two-tab flow is e2e-tested in CI.
