# v0.2.6

Synchronization never ran on React Native, and fixing that exposed two more gaps on the same runtime. Two of the changes are breaking; both are listed under Upgrading first, because `^0.2.5` ranges will receive this release automatically.

## Upgrading

- **`SyncControllerState.cause` is required.** Code that builds a state value by hand, such as the placeholder a React provider returns when there is no controller, adds `cause: null`. Reading the state is unaffected.
- **React Native needs a random source before `Database.open`.** Hermes provides no WebCrypto, so `globalThis.crypto` is undefined there and `randomId()` no longer falls back to `Math.random()`. In Expo Go, define the global from `expo-crypto`, which ships inside it; in a development build or a bare app, install `react-native-get-random-values`, rebuild the app, and import it before opening a database. `Database.open` now probes the source and fails at startup, with a message naming the fix, if it is missing or broken. Browsers, workers and Node are unaffected. Details in [docs/reference/runtimes.md](../reference/runtimes.md).

## Fixed (core)

- Every sync run on React Native threw `TypeError: undefined is not a function` before its first request and retried into the same statement forever, while local writes kept working. `runSynchronize` opened with `options.signal?.throwIfAborted()`; the optional chain guards a missing signal, not a missing method, and Hermes provides an `AbortSignal` without `throwIfAborted`. The engine now reads `aborted` and throws the `reason` itself, at all four abort checks. Verified on a device: the first run after the fix reported `pulled: 1, pushed: 1, rejected: 0` and a record stuck locally for hours landed on the server. Writing `signal?.throwIfAborted?.()` would have stopped the crash and silently skipped cancellation on Hermes, leaving database work running after its owner had logged out.

## Changed (core)

- `SyncControllerState` carries `cause`, the value the failed run threw, beside the `error` message, cleared to null on the next success. The controller had reduced every failure to `error.message`; diagnosing the bug above meant patching the library from outside to recover a stack it had been handed and discarded. `JSON.stringify(state)` drops an Error's stack, so log `state.cause` directly.
- `randomId()` requires `crypto.getRandomValues` and `Database.open` probes it with one byte before touching the driver. The old fallback described itself as covering exotic environments; React Native was the exotic environment, and every id minted on mobile came from `Math.random()`. The probe calls the function rather than checking that it exists, because a polyfill installed without an app rebuild defines the function and throws on call. The two failures carry different messages, and the original error is kept as `cause`.

## Tests

- The Android device lane runs the sync orchestrator before the driver conformance suite: a round trip against an in-process backend, an aborted signal that must stop the run before any traffic, the controller reaching idle, dispose aborting an in-flight run, and ids generating without repeats. `packages/core/**` now triggers that lane; a core-only change previously skipped the one runtime this release is about. All steps passed on the emulator for this release.
- `@remelondb/driver-rn` has adapter tests against a mocked expo-sqlite, covering what the adapter owns. They are not the conformance suite, which needs a device lane for that driver (#43 follow-up).

## Docs

- `docs/reference/runtimes.md` states the host globals core assumes, the two known gaps on Hermes, and who supplies what. The driver-rn README describes both ways an Expo app provides its random source. The maintainer guide covers both changes where a React Native reader meets them.
