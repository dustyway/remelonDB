# v0.1.3

Patch release. All packages move to 0.1.3 in lockstep; the substantive
changes are in `@remelondb/server` and `@remelondb/store-drizzle`.

## Fixed

- A push naming one id in both `created` and `updated` crashed SQL
  stores (Postgres cannot touch the same row twice in one upsert
  statement) instead of getting a protocol answer. The engine now
  resolves duplicates to the last statement, matching the wire spec's
  advisory classification.
- Writes to tombstoned ids whose deletion the client's cursor already
  covers were silently discarded but reported as accepted, leaving the
  pushing device with a phantom record no pull ever corrects. The
  engine now names them in `rejected`. This adds a ninth method to the
  store seam, `tombstonedIds(table, scope, ids)`; the memory store, the
  Drizzle store (with a `TableOverrides` slot), and the reference
  server implement it.

## Added

- Tables can declare `appendOnly: true` in the engine's table config:
  writes to existing ids are rejected by id, creates and deletes still
  apply. For event-log tables this replaces silent `insertOnly` column
  tricks with refusals the client actually sees.
- Conformance cases 11 (duplicate ids resolve to the last statement)
  and 12 (tombstoned-id writes are rejected, never silently dropped)
  pin both behaviors for every backend that runs the suite.

## Docs

- `sync-wire.md` states the two protocol rules explicitly: a ChangeSet
  naming an id twice means the last statement wins, and refusals are
  never silent.
- `server-design.md` reflects the nine-method store seam and the new
  engine responsibilities.

## Breaking

- Custom `SyncStore` implementations must add `tombstonedIds`. Both
  shipped stores and the reference server already have it; stores built
  on `createDrizzleStore` config need no change.
