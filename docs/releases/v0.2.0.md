# v0.2.0

The largest release since the sync protocol landed, and the version number says why: three compatibility changes ship alongside the features, so this is 0.2.0 rather than a tenth 0.1.x patch. All packages move in lockstep. The release closes #13, #15, #16, #17, #19, #20, #22, #23, #25, #27, #28, and #30. It is also the first release whose GitHub page carries the maintainer guide as a downloadable EPUB.

## Breaking

- `QueryResult` and `SelectedResult` gain a required `isPreviousData` field. The hooks always supply it; it is `true` only while `keepPreviousData` shows the previous query's rows. Code that constructs these shapes by hand, such as test doubles, adds `isPreviousData: false`.
- `SyncStoreTx.upsert` may now return refused ids: the type widened from `Promise<void>` to `Promise<void | readonly string[]>`. Existing stores that return nothing keep their exact behavior. A store that returns ids reports per-row storage refusals, which the engine forwards into `rejected`.
- `@remelondb/driver-rn-cpp` requires `react-native >= 0.80`, up from 0.76. The shipped codegen glue calls CMake helpers that React Native added in 0.80, so the old floor never actually compiled; the claim was untested until this release's new CI lane falsified it. CI now compiles the packed package against 0.80.2 and runs the full suite on an Android emulator at 0.86.

## Added (protocol and server)

- Refusals from storage itself land in `rejected` (#16, conformance case 14). A unique or foreign-key constraint that fires during apply rejects that row by id, leaves no trace in storage, and the rest of the push applies. The drizzle store implements this with a batch savepoint on the fast path and per-row savepoints after a violation (Postgres 23505/23503).
- A deletion is the terminal statement for its id (#23, cases 17 and 18). An id named in `deleted` supersedes any created or updated content in the same push, and whatever refuses the surviving statement refuses the id entirely. Before this rule, rejecting the content half could leave the deletion applied while the response claimed the id was rejected.
- The conformance suite grows from 13 to 18 cases, with two new opt-in capabilities: `uniqueColumn` and `crossValidation`.
- The formal model now covers storage refusals (#19) and gained the invariant the original three could not express: `rejectedNoEffect`, an id named in `rejected` holds exactly its pre-push state. A fault flag, `DELETE_LEAK`, reproduces the pre-#23 bug on demand, the same way `SILENT_DROP` keeps the phantom-record fault reproducible.

## Added (client)

- `SynchronizeResult.rejectedRecords` (#25) names the refused ids per table. The existing `rejected` count is unchanged and both derive from one map, so `rejectedRecords` is `{}` exactly when the count is 0. A status indicator that treats every non-throwing sync as clean is lying whenever the count is above zero; the rejection-handling recipe in sync-basics.md shows the controller pattern.
- `Model.prepareUpdate(builder)` (#30) builds an update as a `BatchOperation`, completing the prepared quartet with `prepareCreate` and the two prepared deletes. An update now commits atomically with other operations in one `db.batch()`. The cached record stays unchanged until the batch commits, a failed batch leaves it untouched, and a stale handle to a deleted record throws instead of writing onto the tombstone. `update()` delegates through the prepared path, so field collection has one implementation.

## Added (react)

- `useMutation` (#15) wraps an async write: `mutate` returns void and is floating-safe by construction, failures land in `error`, never as unhandled rejections; `mutateAsync` keeps promise semantics for flows that continue only after commit. Under overlapping calls the latest invocation owns `data` and `error`, `isPending` counts every call in flight, and `reset` returns to idle immediately.
- `useQuery` gains an opt-in `keepPreviousData` option (#13). While a changed query loads, the hook keeps rendering the previous query's rows, flagged as `isPreviousData: true`; without the option, behavior is unchanged. Retention is per consumer, never enters the shared store, and drops the moment the database object changes.
- `useDatabaseState` and `useDatabase` memoize their subscription per manager instead of resubscribing every render.

## Docs and tooling

- sync-basics.md gains the rejection-handling recipe (#27): the four caller-visible outcomes of a sync run and the attention-required controller pattern.
- sync-design.md names the third divergence from upstream: per-record rejection as a normative contract where upstream has an unnormed experiment.
- The maintainer guide now tracks main (the version stamp is a floor), went through a full content pass (the SQL injection claim now says what is true, counts corrected), and renders to EPUB: `pnpm guide:epub` locally, validated with epubcheck and attached to releases by CI (#28).
- The tutorial records a review and reschedules its card as one atomic batch, enforces `appendOnly` on the reviews table instead of describing it, warns that observation reacts to writes rather than the clock, and checks `res.ok` before parsing sync responses.
- New CI: the Android emulator runtime lane and the RN 0.80 compile floor (#20), and packed-tarball type checking, committed fixtures typechecked against the real published declarations.
