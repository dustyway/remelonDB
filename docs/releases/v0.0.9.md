# v0.0.9

The server-side release. Two new packages take a sync backend from "bring a store adapter" to running on Postgres behind NestJS with one config object each, the engine's gc-floor path is fixed (it had never been exercised), and the example demo can persist. No changes to the wire or the client.

## New: @remelondb/store-drizzle

A `SyncStore` for Postgres via drizzle-orm. Tables are configured, not coded: point the store at a drizzle table's four machinery columns (`id`, `rev`, `deleted_at`, scope) and every store method is generated — when column names match wire names there is no mapper code at all. Pushes serialize per scope with an advisory lock, pulls run in one repeatable-read snapshot, and revisions come from one Postgres sequence.

Retention is bounded from the start: `gc(floor)` prunes tombstones and persists the floor (never lowered; below-floor cursors degrade to resync), and a per-table `scrub` blanks chosen columns in the same UPDATE that tombstones a row.

Proven, not argued: the store passes the full backend conformance checklist on in-process Postgres (pglite), and the one scenario pglite's single connection cannot host — a push committing during an open pull — is constructed deterministically against real Postgres and runs in CI behind a service container.

## New: @remelondb/nestjs

The wire protocol's canonical HTTP binding as a NestJS module: `POST /sync/pull` and `/sync/push` over any `SyncStore`. Hand it the same per-table Zod objects the client's `zodTable` uses and validation lands at each boundary with the right granularity — the push envelope checks shape and usable ids, the engine checks values per record and rejects by id while the rest of the push applies. Auth stays the app's: `scopeFrom(request)` maps a request to its scope (a session lookup, a JWT claim); null answers 401.

The package's test suite runs the conformance checklist through real HTTP — NestJS app, `fetch`, memory store — so what passes in-process is shown to survive the transport.

## Fixed: the gc-floor path in the engine

Implementing a store with real GC exposed that the floor path had three related bugs, all from one cause: after pruning, a scope's live max revision can sit below the floor, and a quiet scope's max may never reach it. Full pulls answered `resyncRequired` forever, at-floor cursors read as unknown, and quiet scopes could never sync again. The engine now treats served history as extending to the floor — full pulls bypass the floor check (a snapshot carries no deletions), the effective max is `max(maxRev, floor)`, and issued cursors never fall below the floor. Regression-tested against the memory store and the drizzle store.

Also in the engine: malformed pushes throw a typed `SyncProtocolError` (transports match on the class, not the message), and the conformance suite exports its `pulled`/`accepted` assertion helpers for backend test suites.

## Example

The todo-sync backend now takes a `DATABASE_URL`: unset, the in-memory store as before; set, the same schema's keys become a Postgres table via `@remelondb/store-drizzle` and the list survives restarts. The demo image is a two-stage `pnpm deploy` bundle — 394MB instead of 1.55GB, no toolchain or devDependencies at runtime.
