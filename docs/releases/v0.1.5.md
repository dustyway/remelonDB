# v0.1.5

Patch release. All packages move to 0.1.5 in lockstep; the substantive
change is in `@remelondb/nestjs`.

## Fixed

- The NestJS module builds its own sync engine and passed only Zod
  validation into it, so engine table config such as `appendOnly` could
  not reach the served `/sync/push` at all. An app could configure
  `appendOnly` on an engine of its own, test against that engine, and
  run the module's unprotected engine in production. `RemelonSyncModule`
  now takes `tableOptions`, per-table engine config beyond validation:

  ```ts
  RemelonSyncModule.forRootAsync({
    useFactory: () => ({
      store,
      tables: { review_events: ReviewEvent },
      tableOptions: { review_events: { appendOnly: true } },
      scopeFrom,
    }),
  })
  ```

  Validation still always comes from `tables` and cannot be overridden.
  A module test now pushes a rewrite through the module's own HTTP
  endpoint and expects the by-id rejection.

## Docs

- The backend reference and the nestjs README state the rule that made
  this a trap: the module builds its own engine, so config not passed
  through the module does not exist on the served endpoints.

## Breaking

- None.
