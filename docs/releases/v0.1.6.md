# v0.1.6

Feature release. All packages move to 0.1.6 in lockstep; the
substantive changes are in `@remelondb/core`.

## Added

- `synchronize` accepts `validatePullResult` and `validatePushResult`,
  run on every untrusted server response — the initial pull, the
  re-pull after `resyncRequired`, and the push acknowledgement —
  before core inspects a variant, writes records, marks local changes
  synced, or adopts a cursor. A throw fails the sync with local state
  untouched. Validators are parse-shaped (core adopts the return
  value), so `syncSchemas()` parsers slot in directly. Hand-rolled
  validation in the adapters covered only the call sites you
  remembered; this covers the paths it tended to skip.
- `observe` and `observeCount` take an error callback. A failed
  re-fetch previously surfaced as an unhandled rejection and a list
  that silently stopped updating; now it reaches the subscriber. A
  subscriber that itself throws is an app bug and is deliberately not
  routed there. Opt-in refetch diagnostics ride along.
- The react hooks wire the error through: `useQuery`'s `error` field
  fires on refetch failures (retaining the last successful rows),
  clears on the next successful emission, and reaches every consumer
  of a shared subscription. New `useQueryCountResult` exposes the
  count observation as `{ data, isLoading, error }` beside the plain
  `useQueryCount` number.
- `select` recomputes when the selector's identity changes, so
  selectors closing over changing props stay correct without
  restarting the observation.

## Docs

- `reference/sync.md` explains what the validators buy over parsing in
  your own adapter, and the parse-shape contract.
- `reference/database.md` explains why observation failures need the
  second argument.
- `examples/todo-sync` demonstrates the validators; its adapters are
  pure transport now.

## Breaking

- None.
