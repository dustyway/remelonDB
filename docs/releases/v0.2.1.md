# v0.2.1

Core now ships the client half of the wire contract. Until now every consumer wrote the same two pieces above `synchronize()` by hand: an HTTP adapter that classifies responses, and a background loop that decides when runs happen. Both are in core now, tracked as #37. No breaking changes; all packages move in lockstep.

## Added (transport)

- `@remelondb/core/transport`, a dependency-free subpath. `createSyncTransport({ post, validatePullResult, validatePushResult })` returns the `pullChanges`/`pushChanges` pair for `synchronize`, enforcing the protocol/transport split: `conflict`, `resyncRequired`, and per-record rejections pass through as data, while a non-2xx, a network failure, a malformed body, or a wire-invalid shape throws `SyncTransportError` (with the HTTP status when there is one) and the run fails with local dirty state untouched. Validators are required and use the shape `synchronize`'s own `validatePullResult` accepts, so `syncSchemas` from `/zod` plugs in directly; skipping validation takes an explicit identity function.
- `createHttpPost({ baseUrl, headers?, credentials? })` covers the canonical `post`: JSON body, signal forwarded, `credentials` passed through, and a `headers` thunk called at the start of every request so credentials that change, such as a native session cookie, are always current. Anything it cannot express is a hand-written `post`; the option list stays at three.
- `readSyncResponse(path, send)` is the classification alone, for apps that write their own `post` but keep the same error handling.

## Added (controller)

- `createSyncController(options)`, a root export beside `createDatabaseManager`. It owns when syncs happen: one on `start()`, an interval (`intervalMs`, default 60s, `null` disables the clock), platform wake-ups through a `triggers` subscribe function, and a debounced run after `notifyLocalWrite()`. Runs are single flight; triggers during a run coalesce into at most one follow-up. `syncNow()` is the manual trigger and re-arms after an auth error; a fully manual app skips `start()` entirely. `dispose()` aborts the in-flight run through the signal `runSync` receives, then goes silent; dispose before closing the database. Errors classify through `isAuthError` and `isOfflineError` predicates defaulting to the transport's 401 and no-status cases. State (`idle`/`syncing`/`offline`/`error`/`resync-required`, `lastSyncAt`, `lastResult`) is data for the UI; a run with rejections stays `idle`, and what `rejected > 0` means is the app's decision.
- `createRunSync(options)` adapts `SynchronizeOptions` to the controller's `runSync`, returning `resynced`, `rejected`, and `rejectedRecords`.

## Added (react)

- `useSyncState(controller)`, the sync sibling of `useDatabaseState`: a controller's state as a tear-safe subscription, re-rendering exactly on transitions.

## Docs and example

- The sync reference gains transport and controller sections; the tutorial's §10 teaches the transport and §11 wraps the manual run in a controller with a CI-executed block; sync-triggering's trigger set now plugs into the `triggers` option; react.md documents the hook.
- `examples/todo-sync` consumes all of it on web and native: `createHttpPost` + `createSyncTransport` in the shared client, one controller per database, badges through `useSyncState`. The e2e suite passes unchanged against the rewritten client.
