# v0.2.2

store-drizzle now publishes CommonJS artifacts next to the ESM pair, fixing type-checking for CommonJS consumers. No API changes; all packages move in lockstep.

## Fixed (store-drizzle)

- The package published ESM-only (`index.mjs` + `index.d.mts`). Node loads that fine from CommonJS via `require(esm)`, but a `.d.mts` is type-checked in import mode, so its `drizzle-orm` references resolved to drizzle's import-mode declarations while a CommonJS consumer's own drizzle imports resolved to the require-mode set. TypeScript treats those as two unrelated `Column` classes, and drizzle's protected members make the mismatch a hard error: table configs and `DrizzleDb` could not be assigned without `as unknown as` casts, and `drizzleSyncTable` failed the same way. The v0.1.9 claim that a typed schema configures `createDrizzleStore` with no casts held only for import-mode consumers.
- The exports map now has `import` and `require` conditions; require-mode consumers get `index.d.cts`/`index.cjs`, whose drizzle references resolve to the same declarations the consumer uses. One module identity, casts droppable. Verified against a CommonJS `nodenext` fixture: bare table-config and `DrizzleDb` assignments type-check with no casts, and `require()` of the package keeps working.
- Only store-drizzle goes dual: its types re-export drizzle's nominal classes across the mode boundary, which is what made the split observable. The other packages keep single-format ESM; their public types are structural, and `require(esm)` (Node >= 20.17) covers the runtime.

## Tooling

- `scripts/sync-exports.mjs` understands a per-package `dualFormat` flag and derives the nested `import`/`require` publish map from it; the tsdown config gains `format: ['esm', 'cjs']` for this package.
