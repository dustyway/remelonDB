# v0.2.5

Adds `useSessionDatabase`, a React hook that owns the per-user database lifecycle. No changes to existing APIs; all packages move in lockstep.

## Added (react)

- `useSessionDatabase({ userId, createManager, sync, controller })` returns `{ manager, syncController, closeError }` and owns what apps were writing by hand: one manager per signed-in user, a sync controller running whenever that database is ready, dispose before close, and the next session's open queued behind the previous close. It renders nothing, so callers wrap the tree in `DatabaseProvider` themselves.
- Sync attaches from the manager's state rather than from one `init()` call. A database recovered by something else, such as an error banner's Retry, still gets sync, and a reopen after an error hands back a different `Database`, so the controller is rebuilt against it instead of pointing at the old one.
- `createManager`, `sync`, and `controller` are read when a session starts, so fresh object literals on every render do not restart the database already open. The result is tagged with its owner, so the render React does after a session change but before cleanup returns nulls rather than the previous account's database.

- A session's manager is not created until the previous session's close has finished, so a caller is never handed a manager it could open ahead of that teardown. Cleanup closes immediately rather than queueing, since `close()` is what invalidates an open still in flight.
- A close that fails stops the next session instead of starting one, and `closeError` carries the failure. The database may still be open, and a replacement over the same file is what this hook prevents.

## Note on placement

The close queue lives in the hook, so it lives as long as the component calling it. It has to be called from something that stays mounted across session _and_ route changes, with route layouts reading the manager from context. Calling it inside a layout the router unmounts brings back the race it prevents: the queue is empty again on remount. This is documented next to the hook, and nothing in the types enforces it.
