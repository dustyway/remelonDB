# v0.1.7

Feature and resilience release. All packages move to 0.1.7 in lockstep;
the substantive changes are in `@remelondb/driver-web` and
`@remelondb/core`. Developed and field-verified through four `dev`
dist-tag prereleases against a live staging deployment.

## Fixed (driver-web)

The shared-worker driver's multi-tab layer was hardened end to end
after its first production deployment surfaced a family of ordering
bugs. Each fix carries a browser regression test (chromium and
firefox):

- SAH pool acquisition retries with backoff while a dead holder's
  handles are released by the browser, instead of surfacing
  `NoModificationAllowedError` to a retry button.
- On Firefox the broker hosts the SQLite compute worker itself
  (`SharedWorkerGlobalScope` has the `Worker` constructor there), so
  page navigation can no longer orphan the pool — previously any full
  page load left handles locked for the session. Chromium and WebKit
  keep the tab-hosted bridge; a hosted worker that fails to load falls
  back to tab hosting instead of hanging.
- An epoch reset (the compute worker died) now requeues pending
  requests, respawns, restores every held database on the fresh
  compute, and replays — a surviving tab keeps working and a newly
  arriving tab is never shown an error for another tab's death. A
  send watchdog probes a silent compute so a lone survivor cannot
  hang. Ping probes are excluded from respawn bookkeeping (their
  self-addressed ports could swallow the respawn).
- Two tabs cold-opening the same database simultaneously both succeed:
  a second open joins even before the compute exists, and first-open
  schema setup ships DDL and version stamp as one atomic batch — a
  client losing the setup race adopts the winner's work instead of
  failing on the collision (`table already exists` / `already open`).
- The published dist carries a resolvable nested worker URL, so
  consumer bundlers can build the broker's self-hosted spawn.

## Added (core)

- `manager.close()`: tears down the open database and returns the
  manager to `idle` so a later `init()` starts fresh. An open still in
  flight when `close()` is called is discarded on arrival — closed
  immediately, its `init()` rejecting — so a slow open can never
  resurrect a database after logout. The tutorial gained a "multiple
  accounts on one device" section around it.

## Testing

- Browser suites (47 tests) now run in CI on chromium and firefox,
  with webkit advisory.
- A seeded chaos suite runs randomized multi-tab interleavings with
  compute kills, asserting no hangs, only designed errors, and exact
  acknowledged-write convergence.
- `scripts/staging-acceptance.mjs` drives real browsers at a deployed
  app for the multi-tab scenarios unit suites cannot express.
- A Vite production smoke test (build from packed tarballs, drive in a
  browser) runs in CI and catches dist-only breakage.

## Release infrastructure

- Prerelease tags (`v*-*`) publish to the `dev` dist-tag and skip the
  GitHub release, so `latest` only ever points at a blessed release.

## Breaking

- None.
