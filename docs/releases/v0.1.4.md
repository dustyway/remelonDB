# v0.1.4

Feature release. All packages move to 0.1.4 in lockstep; the
substantive change is a new `@remelondb/core/react` subpath.

## Added

- React bindings as an optional subpath, `@remelondb/core/react`.
  React is an optional peer dependency; core itself never imports it,
  and the module loads only when imported.
  - `DatabaseProvider`, `useDatabaseState`, and `useDatabase` cover
    the manager lifecycle: one component reacts to
    `taken-over`/`error`, everything else gets `Database | null`
    without the by-hand `status === 'ready'` derivation. The provider
    is optional; every hook accepts an explicit manager.
  - `useQuery` and `useQueryCount` subscribe to live query results.
    Subscriptions are keyed on the query's structure (table plus
    clauses), not object identity: rebuilding an equivalent query
    every render is free, and there are no dependency arrays.
    Components observing structurally equal queries on the same
    database share one refcounted observation.
  - `useQuery` takes a `select` option to derive the rendered value
    per consumer from a shared subscription.
  - All hooks ride `useSyncExternalStore`: safe under StrictMode
    double-mounting and concurrent rendering.
- Tests at both levels: hook behavior over controllable fakes in core,
  and an integration suite in driver-node running the hooks against a
  real SQLite database to pin the Query surface they read.

## Docs

- New reference guide, `docs/reference/react.md`, including a
  migration section for replacing a hand-rolled
  `useState`/`useEffect` bridge.
- The tutorial, database reference, overview, and README point to the
  guide from their observation and subpath discussions.

## Example

- `examples/todo-sync` uses the bindings on both platforms (web
  frontend and React Native client); its local bridge code is gone.

## Breaking

- None.
