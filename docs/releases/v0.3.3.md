# v0.3.3

A core patch release. `createRunSync` dropped what `synchronize` reports about the sync lease, so an app awaiting `syncNow()` could not tell a run that synced from one that did nothing because another context held the lease. `RunSyncResult` now carries it. Every package moves to 0.3.3 together; no other package changes.

## Upgrading

- Nothing to change. `lease` is a new optional field; a custom `runSync` that builds its result by hand keeps compiling and leaves it absent.
- An app that acts on freshly synced data (publishing, "imported") should check `state.lastResult.lease === 'acquired'`, on top of what it already checks: `status` is `idle`, and `rejectedRecords` has nothing of its own. `'acquired'` says the run ran, not that every row got through. With `'unavailable'`, another context held the lease and nothing ran: the zero rejections say nothing about the local changes. The lease lasts as long as the other context keeps syncing (`syncLeaseMs`, renewed on each request), so there is no short wait after which a retry is sure to get it; tell the user rather than loop. With `'lost'`, treat the run as not confirmed as well.

## Fixed: core

- `SyncControllerState.lastSyncAt` no longer advances for a run that returned `lease: 'unavailable'`: that run synced nothing, so "last synced" keeps the time of the run that did.

## Added: core

- `RunSyncResult.lease`: `'acquired'`, `'unavailable'` (another context held the sync lease and nothing ran) or `'lost'` (the lease was refused when asked for again after the push: the server may have taken the changes, the local rows stay dirty for the next run), as `synchronize` reports it. `createRunSync` passes it through, so it reaches `SyncControllerState.lastResult`.

## Tests

- `syncIntegration.test.ts` pins the three values through the controller: `'unavailable'` with no pushed rows, `'acquired'` with the row on the server and marked synced, `'lost'` with the row on the server and still dirty locally.
