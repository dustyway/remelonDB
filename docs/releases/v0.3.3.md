# v0.3.3

A core patch release. `createRunSync` dropped what `synchronize` reports about the sync lease, so an app awaiting `syncNow()` could not tell a run that synced from one that did nothing because another context held the lease. `RunSyncResult` now carries it. Every package moves to 0.3.3 together; no other package changes.

## Upgrading

- Nothing to change. `lease` is a new optional field; a custom `runSync` that builds its result by hand keeps compiling and leaves it absent.
- An app that acts on freshly synced data (publishing, "imported") should check `state.lastResult.lease === 'acquired'`. With `'unavailable'`, another context held the lease and nothing ran: the zero rejections say nothing about the local changes, and the run is worth asking for again shortly.

## Added: core

- `RunSyncResult.lease`: `'acquired'`, `'unavailable'` (another context held the sync lease and nothing ran) or `'lost'` (the lease expired mid-run), as `synchronize` reports it. `createRunSync` passes it through, so it reaches `SyncControllerState.lastResult`.

## Tests

- `syncIntegration.test.ts` pins that a controller whose run was locked out by another context resolves `syncNow()` with `lease: 'unavailable'` and no pushed rows.
